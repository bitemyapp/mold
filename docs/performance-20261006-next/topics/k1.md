# K1: output write-fault preparation (profile-driven follow-up)

This additional independent experiment follows the original15 investigations. Kernel-inclusive lld samples found37.56% of baseline cycles waiting on dirty-folio locks through output write-fault paths, even before accounting for the20.35% advice/zap branch addressed by H1. The existing code already preallocates ext4 disk blocks and advises huge pages; K1 keeps both and tests writable page-table population before concurrent copying.

For Linux/Android ext4 output mappings of at least4MiB, advise MADV_POPULATE_WRITE over exactly the current file length. The address reservation may be twice that length; its unbacked suffix is deliberately excluded. Other filesystems, small files, memory-buffered output and other operating systems retain the existing path. Preparation time is charged in open_file and whole-link timing; a shorter copy phase alone is not success.

Behavior argument: the advice establishes writable mappings without changing bytes. Unsupported/partial-failure cases retain normal demand faults for unpopulated pages. Mapping and descriptor remain owned/alive during the call. The kernel may allocate physical/file pages sooner; memory pressure and serial preparation are performance risks, not reasons to assume a gain. Benchmark machine has over200GiB available memory; no global VM tuning, cache flush, other-process affinity change, or interference with the unrelated workload.

API reference: [Linux madvise manual](https://www.man7.org/linux/man-pages/man2/madvise.2.html), MADV_POPULATE_WRITE (Linux5.14+). The candidate was subsequently implemented, validated and measured in both output modes; results appear below. This is a bounded follow-up, not a claim that prefaulting generally beats demand paging.

Independent review found no blocking ownership/permission/byte-preservation issue. Scope correction: EXT4_SUPER_MAGIC is shared by ext2/ext3/ext4; the experiment is therefore gated to that filesystem family, while only ext4 is measured here. Growth that fits the reserved mapping remains demand-faulted; remapping may populate the new file-backed prefix. See topics/k1-review.md.
