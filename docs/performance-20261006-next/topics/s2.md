# S2: locality across related input and fragment jobs

Independent baseline f8638be9. Worktree /Users/callen/.codex/worktrees/mold-s2-cache-locality/mold; branch codex/mold-s2-cache-locality.

Initial evidence, gathered by root before implementation: 10 perf-stat runs each on lld, Clang, rust-analyzer. All hardware events were scheduled 100%. lld averaged 453 CPU migrations per link, Clang 842, rust-analyzer 641. Clang recorded 95.66M generic cache misses / 424.69M references; rust-analyzer 84.55M / 284.63M. Generic perf cache events do not by themselves measure a cross-L3 penalty or attribute it to string merging. File artifacts under results/baseline-*.stat.csv retain raw evidence and event uncertainties.

Topology read confirms one NUMA node. Benchmark CPUs32–63 span four L3 domains, each with 8 physical cores. Consequently this investigation concerns cache-domain handoffs, not remote-NUMA traffic. No host configuration or unrelated workload is modified.

Next measurement-only instrumentation records endpoint CPU/worker identity for MergeInfo split and resolve, weighted by fragment counts. It uses the captured workstation topology only in an isolated source snapshot and does not affect the production candidate. The goal is to establish whether related phases actually move fragment metadata between cache domains before changing scheduling. Work stealing and OS migration must be distinguished: a changed Rayon worker reflects task placement; a changed endpoint CPU within one task is evidence of OS migration, and an unchanged endpoint does not prove no intervening migration.

Candidate design and acceptance remain evidence-dependent. A global redistribution pass is explicitly excluded because prior M1/M4 measurements already showed its high cost. Root alone performs performance timing.

The bounded prototype was subsequently validated and measured, with separate baseline handoff-count attribution; the final rejection appears below. Selected merge work >=8MiB is partitioned into at most one contiguous member range per merged section per worker, balanced approximately by input bytes. Two Rayon broadcasts send the same ranges to the same worker for split and resolve. Only range descriptors and HLL partials are collected; fragment bytes, hashes, offsets, and canonical hash-table/layout algorithms stay in place. The single-section late resolve fallback is unchanged. Worker identity is not a CPU-affinity guarantee, and this change does not prevent OS migrations. Extra serial assignment and loss of work stealing can overwhelm any cache benefit.

Independent relocation_kernels review found no blocker. Member lists are partitioned exactly once, including zero-byte tails. Workers lock only their matching slot; neither split_contents nor resolve_contents nests Rayon work. The first broadcast joins before map replacement; the second joins before freeze/layout. HLL registerwise-max reduction is exact under regrouping. The dedicated correctness case exceeds 8MiB and compares 1/2/8/32 worker outputs with fewer input members than workers. No unsafe code or host affinity changes are introduced.

The active lld and Clang paths regress in latency with neutral CPU totals. The hello improvement occurs on the unchanged fallback path and cannot be attributed to stable worker ownership. A possible worker-start rotation is gated on assignment counters showing actual skew; it is not an accepted improvement.

Final assignment attribution: the imbalance is within the dominant sections. Exact untimed per-worker bytes/fragment/member matrices were gathered from a separate snapshot, all eight hashes matched, and the proposed per-section worker-start rotation was evaluated statically over those same assignments.

Rotation would not fix this skew, so no production revision or further timing run is justified by that proposal. The initial byte-based partition balances bytes fairly well for lld/Clang while leaving roughly2.2× peak-to-mean fragment counts; a balanced insertion workload would need additional scheduling work that changes the original locality premise. Final decision: reject the prototype and close the bounded investigation. Matrices, build log, source patch, and analysis are retained under topics/s2-assignment-counts. Production worktree and frozen binary remain unchanged.
