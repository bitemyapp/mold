# Optimization investigations: evidence index

All sixteen topic prototypes are independent and start at `f8638be95ae14954ec3b1029e6008128d7a27f1b`. This index summarizes the linked notes; raw measurements and validation logs remain primary. P1 refines PR1696. H1 remains in a separate draft and the experimental combined branch as a conditional tradeoff; the other fourteen ideas were rejected as defaults. Both the prior `1347ca95` stage and latest `75200f10` stage completed their separate measurements and validation. Latest combined source `8e522e52` passed 36 unit tests and 8,028 integration tests across 18 target configurations (1,026 skips, 0 failures), plus formatting and armv7/i686/PowerPC host source checks. Rejected experiments remain in their branches and worktrees.

Positive wall/CPU/RSS deltas mean more cost. Quoted intervals are 95% intervals from same-file interleaved comparisons. Most initial screens have 24 pairs per case; the last reused-output screen has 32. These are measured effects on wx-workstation, not universal guarantees. Tiny C `hello`, Rust `rhello`, LLVM TableGen, lld, Clang, stripped Clang (`clang-s`), rust-analyzer (`ra`) and stripped rust-analyzer (`ra-s`) form the eight-case corpus.

**Output mode matters.** Reused-output runs keep the harness output pathname between links. Fresh-output runs unlink only that output before each link, outside the link stopwatch. Neither mode flushes input caches. The earlier notes' “independent confirmation” means a new run batch, not fresh-output mode. A result in one mode must not be pooled with the other. The coordinator also observed a much cheaper control in later reused-output final runs, with little remaining H1 gain. Output mode alone therefore does not identify the favorable contention state; no before/after causal claim is made about why that state changed.

Validation counts below use passed/skipped/failed for integration tests. Unit counts such as 35+2 mean 35 linker tests plus 2 harness tests.

## Merge strings

| Topic | Mechanism and preserved behavior | Evidence and decision |
|---|---|---|
| [MS1](ms1.md) compact probes | Split pointer/length probe keys from rich values while retaining bucket IDs, probe order and canonical layout. The total nominal bucket storage stays 32 bytes. | **Reject.** Clang wall +4.8% [2.5,9.2], CPU +5.7% [3.6,7.7]. The smaller probe stride did not repay the split-access cost. Unit 35+2, full native 550/14/0, eight goldens. |
| [MS2](ms2.md) occupancy-count reuse | v1 reserves the full shard to skip counting. v2 records exact unique-insertion counts in bounded per-fold arrays, including late synthetic comment strings; generic maps retain fallback counting. IDs and ordered traversal stay unchanged. | **Reject both.** v1 Clang CPU +15.3% [3.9,21.7] with extra scratch reservation. v2 removed that confound but all eight wall intervals include zero; ra-s CPU +1.32% [0.27,2.79]. v2 unit 35+2, full native 551/14/0, eight goldens. |
| [MS3](ms3.md) bounded vector reservation | Estimate string density from the first 64 naturally visited strings, reserve bounded offset/hash storage, and retain ordinary growth fallback. No extra full scan. | **Reject.** TableGen wall +5.6% [0.7,8.9], CPU +7.1% [0.2,12.3], RSS +33.7%. Separate untimed counters show fewer reallocations but excess capacity: Clang 266.69→493.80 MiB summed end-of-split capacity. That sum is not simultaneous RSS. Unit 33+2, full native 551/14/0, eight goldens; 48 separate counter links matched. |
| [MS4](ms4.md) dense rich records | Four-byte lookup indices point into per-shard dense unique records. External bucket IDs, equality, canonical order and publication discipline remain intact. | **Reject.** lld wall +6.0%, Clang +8.7%, ra +6.1%; modest RSS savings of 3.1/1.3/2.2% did not justify latency. The extra index dependency and unique-record reservation remain real costs. Unit 36+2, full native 550/14/0, eight goldens; independent source review. |

| Topic | Mechanism and preserved behavior | Evidence and decision |

| [CR2](../notes/cr2.md) repeated-fragment hint | Try the previously resolved fragment after the existing next-fragment hint, before the unchanged binary-search fallback. ## Scheduling and the other profiled costs

| Topic | Mechanism and preserved behavior | Evidence and decision |
|---|---|---|
| [S1](s1.md) phase concurrency | Experimental environment caps create a smaller pool for merge, copy or GC only; pool creation is included. Other work can still use the normal pool, so this is not a process-wide cap. | **Explicit tradeoff, not a general default.** In the initial four-case same-binary 20-pair comparison, copy cap 8 saved lld wall 7.8% and CPU 42.2%, but ra wall rose 14.9%; Clang CPU fell 27.0% while wall rose 2.8%. TableGen's normal 12 workers make cap 16 a no-op. Targeted native 15/0/0. Wider 32-pair copy-cap results are preserved in screen-fifth; no blanket cap is selected here. |
| [S2](s2.md) split/resolve worker locality | Assign contiguous byte-balanced member ranges to the same workers for split and resolve, for selected merge work ≥ 8 MiB. Hash/probe/order semantics remain unchanged. | **Reject.** lld wall +1.9% [1.1,3.0], Clang +2.8% [1.7,3.7], CPU neutral. Untimed endpoint counters observed frequent cache-domain handoff but did not prove its time cost. Static rotation did not fix fragment skew. Targeted native 9/0/0, eight goldens; four cases exercise the path. |
| [G1](g1.md) compact GC targets | Resolve symbols to typed section/fragment/DSO targets before marking. Original relocation edges, liveness state and special start/stop paths remain authoritative. | **Reject after confirmation.** A 24-pair ra wall hint of −3.9% weakened to −1.9% [-4.0,1.2] in an independent 50-pair repeat, with CPU +0.1% [-1.3,1.6]. The cache's preparation and memory were not justified. Targeted 23 and full native 550/14/0; eight screen goldens. |
| [P1](p1.md) demand-sized symbol blocks | Count inputs in file-major order, skip empty shards and use smaller allocation blocks for small shards. Unique-name identity, repeated gathers and initialized storage remain preserved. | **Included in the combined branch.** Latest standalone reused-output hello wall −10.97% [-14.56,-9.09], CPU −11.48% [-15.00,-9.47]; fresh-output wall −9.58% [-12.99,-7.11], CPU −9.91% [-12.86,-7.39]. No reliable large-link wall regression in those screens. v1 full native 550/14/0; v2 unit+14 targeted tests; test-only semantic follow-up passed. Both modes' eight goldens match. |
| [H1](h1.md) batch output advice | Preserve ordered 4 MiB shard hashes and build-ID bytes, then issue one mapping-advice call after hashing joins. | **Retained in the experimental candidate as a conditional tradeoff.** Earlier 32-pair reused-output lld wall −8.37% [-8.92,-7.78], CPU −17.48% [-20.60,-14.53]; Clang wall −4.54%, CPU −21.62%. Fresh LLVM results are neutral; ra-s fresh wall +3.23% [0.50,5.66] was not confirmed as a reliable regression in the final combined 50-pair check (ra-s +0.73%, interval [-1.82,2.51]). Later reused-output final runs also show a much cheaper control and little remaining gain; the earlier result does not establish a stable repeated-link speedup. v1 full native 550/14/0; cleanup release/build-ID test; both modes' eight goldens. |
| [H2](h2.md) early completed-shard hashing | Hash whole completed nonallocated output shards during copy and reuse digests at the final build-ID barrier, with conservative output/architecture exclusions. | **Reject.** TableGen wall −3.05%, CPU −9.25%, but lld wall +2.72% [1.25,4.04] and Clang +2.44% [0.20,4.58]. Moving work onto copy workers was not a general improvement. Release/unit/full native 550/14/0, eleven-mode oracle fixture and eight goldens. |

CPU savings do not erase those latency costs. Local logs confirm release/unit 33+2/full native 550/14/0; both modes' eight goldens match. |

## What the profiles explain

[Kernel-inclusive H1 attribution](../notes/h1-kernel-attribution.md) traces substantial lld cycle samples to ext4 dirty-folio locking through page-table cleanup and shared-write faults. It does not identify those as mold mutexes. H1 reduces the cleanup branch; initial output dirtying remains. Sequential diagnostic profiles explain a mechanism but do not substitute for the interleaved wall/CPU comparisons, and fresh-output measurements and the later cheaper reused-output control show that the payoff varies with the measured contention state. The exact state change is not isolated, and the reused/fresh label alone does not explain it.

Allocation and locality counters are separate untimed attribution runs. Production timing uses frozen binaries; measurement-only patches are retained separately. The manifests and [CSV export definitions](../report-data/README.md) distinguish source commits, current branch heads, environment overrides, output modes, final hashes and partial versus complete result groups.
