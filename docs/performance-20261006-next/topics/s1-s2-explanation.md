# Scheduling experiments: what the controls mean

S1 changes the number of workers available to one foreground phase. A link keeps its normal pool for reading inputs, symbol work, and other phases; only merge resolution, output copying, or section GC enters an extra pool with eight or sixteen workers. Pool creation is charged to the link. The sweep includes the same binary with no cap, so we can distinguish the cap’s effect from incidental code-layout changes. Background GDB work can still run in the normal pool, and compressed-debug preparation copies some data outside the output-copy wrapper. This is a phase concurrency experiment, not a cap on the whole process.

The key question is whether fewer concurrent workers reduce contention enough to compensate for lower parallelism and pool startup. A lower CPU total with a slower link is a tradeoff, not an unconditional improvement. The result must also survive the smaller tblgen workload, where pool startup is a larger fraction of total time. The sweep retains adaptive default thread selection; a requested cap at or above that count is an unchanged-path control. No machine-wide CPU or affinity settings change.

S2 asks whether successive passes can reuse the same input data on the same worker. Baseline instrumentation recorded the CPU and Rayon worker at the end of string splitting and the beginning of fragment insertion. About 74% of lld and Clang fragments, and 78% of rust-analyzer fragments, moved between L3 domains. Only 5%, 2%, and 6% respectively stayed on the same worker. These are fractions of fragments, not fractions of execution time.

The workstation has one NUMA node. Its benchmark CPU set spans four L3 domains, so these counts concern cache placement rather than remote-NUMA traffic. The instrumentation samples task endpoints; it cannot count intervening migrations that return to the same CPU. The small endpoint migration counts therefore do not supersede whole-link scheduler counters.

The S2 prototype assigns contiguous, approximately byte-balanced input groups to fixed Rayon workers for both passes. It does not redistribute fragment bytes or replace the canonical hash table. Its expected benefit is better reuse of hashes and fragment offsets; its risks are serial assignment cost and uneven work that cannot be stolen. Worker identity also does not guarantee CPU affinity. The changed task partition affects HLL partial aggregation as well, so a timing improvement alone would not prove a cache explanation. Golden hashes, phase timing, and hardware counters must support any such claim.

The stable-ownership path covers tblgen, lld, Clang, and rust-analyzer. The other four corpus cases remain on the original path because their selected merge input is below the 8 MiB threshold. The baseline handoff statistics include both paths and are not themselves a performance benchmark.
