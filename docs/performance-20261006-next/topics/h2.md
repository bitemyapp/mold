# H2: hash completed output shards while other copy jobs run

Independent branch `codex/mold-h2-pipelined-hash` from f8638be9. Prototype is restricted to x86-64, hash build IDs, no emitted relocations, no relocatable output, and no endbr rewriting. After an Output or Merged nonallocated chunk finishes copying and relocating, hash each whole4MiB global shard wholly contained in its exclusive slice. Store its32-byte digest in a OnceLock array. The final build-ID pass reuses these hashes, computes all remaining shards normally, and performs the existing advice/hash-of-hashes/write.

Behavior argument: disjoint mutable copy slices prevent read/write overlap; each digest has a unique shard index and one writer. In-chunk alignment and thunks are finalized before its copy task returns. Later .rela.dyn sorting, build-ID writes, and section-header rewrites concern different chunks. GDB-index completion reads relocated debug bytes, appends its own bytes, and rewrites the section-header chunk; it does not change these hashed ranges. Only whole shards are hashed early, so later output extension cannot change an early partial shard. Emit-reloc paths that can patch other chunks and architecture-wide finalization are disabled. Endbr rewriting is excluded even for unusual nonallocated executable sections. Inter-chunk padding never intersects eligible ranges. Existing hash partitioning, concatenation order, and zero build-ID slot semantics are retained.

No extra unsafe code. Risks are scheduling overhead and delaying a copy worker that otherwise helps critical relocation work; the hypothesis requires end-to-end improvement, not just a shorter final hash timer. Full output hashes and native tests were required and subsequently passed; the measured rejection is recorded below.
