Baseline build-ID work is roughly6–7% of large LLVM internal wall time and combines hashing with one MADV_DONTNEED call per4MiB output shard. The prototype keeps exact4MiB shard hashes and final hash-of-hashes but issues a single advice over all bytes after the first shard, after hashes complete.

Behavior argument: advice affects only process page-table entries of the shared file mapping; bytes remain in the file/page cache. First shard is retained for the build-ID write as before. Shard boundaries, hash order, digest truncation, and build-ID bytes are unchanged. Advice can serialize kernel cleanup and therefore could regress latency; measurement must include system CPU and close time. No floating point/RNG changes.
