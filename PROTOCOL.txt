Hypotheses from original PR evidence:
1. Short bursts lose time to sleeping-worker wake-up cascades. Replacing
   mold's broadcast polling jobs with a 2 ms Rayon idle timeout should retain
   much of the latency benefit. Impact 4, confidence 4, effort 2: score 8.
2. Sequential thread creation and readiness wait add fixed startup latency.
   Native asynchronous global construction should match #1695's local-pool
   workaround. Impact 4 (small links), confidence 4, effort 2: score 8.
The original PRs already profile these runtime costs; this experiment tests
runtime ownership and compares measured end-to-end performance.

Behavior argument: neither change alters linker data, ordering, tie breaking,
floating point, or RNG. Idle timeout extends only pre-sleep search; job-event
counter/latch/condition-variable protocol is preserved. Async startup queues
valid worker descriptors before publishing the same global registry; pool
size and per-worker queues are fixed, and jobs may execute as workers start.
Late spawn failure is fail-stop to avoid stranding broadcast jobs. Golden
outputs must match all arms apart from an ELF producer/version identification
if source version recording makes that differ; any exception must be inspected.
